-----------------------------------------
Mục tiêu: gọi LLM như một API service bình thường, có kiểm soát.
  - [x] Messages API: system/user/assistant, temperature, max_tokens, stop
  - [x] Structured output: JSON schema / response format, ép model trả đúng cấu trúc
  - [x] Function calling / tool use: model gọi hàm của mình, mình trả kết quả về
  - [x] Streaming (SSE) — quan trọng cho UX và cho backend timeout
  - [x] Prompt patterns: few-shot, chain-of-thought, role prompting, prompt template
  - [x] Xử lý lỗi: rate limit, retry + backoff, context length exceeded, refusal
Thực hành: [x] viết 1 client wrapper (Python) có retry, logging token, đổi model dễ (shared/llm_client.py).
Tài liệu: Anthropic API docs, OpenAI cookbook.

2. [~] RAG + EMBEDDINGS + VECTOR DB   <-- trùng hướng DB của bạn — GẦN XONG (còn thiếu so sánh vector store khác + đóng gói thành API)
------------------------------------------------------------
Mục tiêu: cho LLM trả lời dựa trên tài liệu riêng, không bịa.
  - [x] Embedding là gì, cosine similarity, kích thước vector
  - [x] Chunking: cách cắt tài liệu, overlap, metadata
  - Vector store:
      * [x] pgvector (Postgres extension) — ƯU TIÊN, vì bạn theo hướng DB
      * [ ] Qdrant hoặc Chroma để so sánh
  - [x] Retrieval: top-k, hybrid search (BM25 + vector), re-ranking
  - [x] RAG pipeline: ingest -> embed -> store -> retrieve -> augment prompt -> generate
  - [x] Đánh giá RAG: retrieval hit rate, faithfulness, answer relevancy (hit rate + MRR đã có, faithfulness/answer relevancy qua LLM-judge chưa làm)
  - [x] Các lỗi RAG thường gặp: chunk sai, retrieve không liên quan, context nhồi quá nhiều
Thực hành: PROJECT 1 (xem phần B) — [~] core pipeline xong, còn thiếu bọc FastAPI + log token/cost/latency.

  - [x] Giới hạn: max steps, timeout, chi phí leo thang, hallucinated tool call

  - [ ] Khi nào KHÔNG cần agent (workflow cố định thì viết code thường rẻ + ổn định hơn)

4. [~] LLMOps — TỐI ƯU CHI PHÍ & VẬN HÀNH   <-- đây là phần "tiết kiệm" + kỹ năng DevOps — ĐANG LÀM
-----------------------------------------------------------------------------------
Mục tiêu: chạy LLM trong production rẻ, ổn định, đo được.
  - [x] Chọn model theo task: model nhỏ/nhanh (Haiku) cho task đơn giản,
    model mạnh (Sonnet) cho task khó — model routing
  - [x] Prompt caching: cache phần prompt lặp lại -> giảm chi phí + latency đáng kể
  - [x] Batch API: task không cần real-time -> rẻ hơn ~50%
  - [x] Token budget: đếm token trước khi gọi, cắt context, nén lịch sử hội thoại
  - [x] Observability: trace từng call, cost, latency, token (tự viết logger; chưa dùng Langfuse/Phoenix)
  - [x] Evaluation: tạo eval set, chấm điểm output (LLM-as-judge, assertion, regression test)
  - [x] Đưa eval vào CI: prompt thay đổi -> chạy eval -> không regression mới merge
    (GitHub Actions: .github/workflows/eval.yml, chạy module4_llmops/eval_05.py, đã verify pass thật trên runner Linux)
  - [ ] Guardrails: lọc PII, chặn prompt injection, kiểm tra output
Thực hành: PROJECT 3 — [ ] chưa làm.

PROJECT 1 — [~] RAG SERVICE trên tài liệu nội bộ — pipeline xong, thiếu lớp API/log
-------------------------------------------
Stack: Python + FastAPI + Postgres + pgvector
  - Ingest: nạp file (md/pdf/txt), chunk, embed, lưu vào pgvector
  - API: POST /ask -> retrieve top-k -> build prompt -> gọi LLM -> trả lời + nguồn
  - Có eval set (~20 câu hỏi + đáp án mong đợi), script chấm điểm
  - Log: mỗi request lưu token vào / ra, cost ước tính, latency
Học được: RAG, vector DB (khớp hướng DB), API design, đo lường.

PROJECT 2 — [ ] AGENT tự động hoá task dev — chưa làm
-------------------------------------
Ý tưởng: CLI đọc 1 issue/ticket -> phân tích -> đề xuất fix + sinh test case
  - Tool: đọc file repo, search code, chạy test, đọc git log
  - Vòng lặp agent có giới hạn số bước + budget
  - Output: markdown report (phân tích + patch gợi ý + test)
Học được: agent loop, tool design, MCP, biết khi nào agent là thừa.

PROJECT 3 — [ ] LLMOps DEMO — chưa làm
----------------------
  - Deploy 1 model local bằng Ollama (hoặc vLLM)
  - Router: task đơn giản -> local model; task khó -> API model
  - Cache layer (Redis) cho prompt lặp; fallback khi provider lỗi
  - Langfuse: dashboard cost / latency / token theo endpoint
  - Eval chạy trong GitHub Actions: đổi prompt -> chạy eval -> chặn regression
Học được: LLMOps, self-hosting, observability, CI — trực tiếp là kỹ năng DevOps.
